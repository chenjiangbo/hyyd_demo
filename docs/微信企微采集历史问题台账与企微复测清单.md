# 微信与企微采集历史问题台账与企微复测清单

更新日期：2026-10-26

本文汇总开源工具验证、寰宇医道集成和 Windows 手测中已出现的问题，供后续企微端到端测试和问题定位使用。它是测试导航，不替代逐项测试报告。

状态说明：

- **已在源码调整，待 Windows 产品包复测**：改动尚未通过客户 Windows 安装包验证。
- **上游/独立工具验证，产品集成未通过**：证明源数据有能力，不代表寰宇医道当前包能采到。
- **未验证**：没有足够的 Windows 实际结果。
- **已确认的产品规则**：测试时按该行为验收。

### 图片、文件和合并消息

| 曾遇到的问题 | 当前结论 | 企微复测时要看什么 |
|---|---|---|

### 工具、界面和 Windows 构建经验

- 企微上游验证工具带图形界面，默认数据脱敏开启，且采集操作是手动全量扫描；这不是客户产品目标。集成时只取核心读取/解析代码，不要求安装或展示上游 GUI，也不能把 GUI 全量扫描当作增量能力。
- 微信上游工具在 Windows Python 3.13 下安装 `winsdk` 失败，独立 Python 3.12.10 环境安装成功。客户产品使用打包后的采集 EXE；这条环境记录只用于复现上游工具，不代表客户应安装系统 Python。
- 企微 Rust 构建曾遇到 Rust 临时目录写权限、调试符号占用超过 2.6 GiB 导致 LNK1104、rustup 试图联网失败。后续使用已安装工具链和离线缓存完成诊断构建。客户企微数据库、注册表、子进程生命周期和最终打包必须在 Windows 验证；Mac 构建不能代替。
- 独立企微工作台的屏幕捕获多次超时，用户手动操作继续完成数据验证。需要用户在 Windows 登录、切换企业、发送/打开消息时，应明确告知用户动作；不能因为截图超时就猜测 UI 状态。
- 1.0.2 包曾出现微信子进程运行而企微采集子进程未运行；1.0.3 增加了持久日志和托盘状态。后续包仍需检查实际健康状态。浮动精灵上的采集状态是用户要求的 TODO，当前托盘/日志只是测试期状态查看方式。
- 安装包后来降至约 129 MB，但 sidecar 资源仍在打包配置内。不能据体积变化断言 sidecar 已移除；如需减包，测量实际产物再单独处理。

## 二、企微最终包复测顺序

每轮先确认 Windows 上运行的企微版本、当前 profile 和对应数据目录。不要先用会话标题判断企业是否正确。

1. **启动与身份**：寰宇医道先启动、企微后启动；企微先启动、寰宇医道后启动；企微退出后重启；切换企业后重启寰宇医道。每种情况都记录状态、日志和使用的数据目录。
2. **规则**：保存一套全局标题规则；确认目标会话命中、非目标会话不采集正文；运行中新增规则后记录实际生效时间；后台离线重启时核对本机最后一份规则。
3. **增量与时间**：在企微窗口最小化时发送连续两条文本，记录发送时间、源表游标、后台到达时间、会话顺序；重启采集进程/客户端后确认游标续读且无遗漏、无重复。
4. **普通图片和文件**：图片先不打开、再打开；小文件先不手动处理、大文件先不下载、之后点击下载。分别记录消息元数据、源端本地文件状态、后台附件状态与实际可打开结果，并等待最多 5 分钟的附件回查周期。
5. **合并消息**：分别准备文字+图片、文字+文件的企微合并卡片；条件允许时再加视频/位置。先保持未打开/未下载，确认父子结构、子项类型和来源时间；随后打开/下载，确认附件补采、子项顺序及后台文件。
6. **重复采集和恢复**：同一批消息再次被读取时，核对消息数不重复增加；后端短暂离线、企微退出、客户端重启后核对消息游标和附件状态恢复。
7. **数据核对**：按指定会话比较源端可见消息、采集器输出、后端消息数和附件数；解释每一条缺失/歧义。仅看到健康状态、非空响应或总数增加都不算通过。

对图片、文件、合并消息至少各留“未打开/未下载”和“打开/下载后”两个状态结果。企微之前的上游 GUI 通过，不可替代此最终产品包复测。

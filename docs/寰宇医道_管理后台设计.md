## 1. 项目背景

### 1.1 业务背景

我们在为一家叫**寰宇医道**的公司做现场数据采集 demo。寰宇是泰康保险绿通服务的承接方——客户买了泰康的"重疾绿通"等高端医疗险后，碰到求医诉求会进入**泰康 CCM 系统**生成订单（挂号协助 / 陪诊 / 住院 / 检查加急 等），订单被分配到泰康自己的"个人池"后，再由寰宇员工接手提供线下服务。

寰宇员工目前的工作流大量依赖**微信 / 企微 / 电话**与客户沟通，但这些沟通过程**不在任何系统里留痕**。寰宇老板想做"客户旅程数据资产化"——把员工在服务中产生的所有沟通素材采集下来，用于后续的客户洞察 / 培训 / AI 还原。

### 1.2 这次 demo 的目标

下周（≈ 2026-06-15 起）我们会去寰宇现场**给 2 名员工装上这套采集系统，运行 1-2 周**，把真实的客户素材采回来。流程：

```
泰康 CCM ──(chrome 插件采集)──→ 后端 PostgreSQL + MinIO
                                       ↑
员工微信/企微对话 ──(粘贴到 tray-app)──┘
员工手机录音 / 通话 ──(手机端 app 上传)──┘
员工电话语音/总结 ──(tray-app 手工录入)──┘
```

老板（**本文档使用者**）安装完会回公司，**不会一直在现场**，所以需要一个跑在阿里云 ECS 上的**管理后台**远程查看采集情况、发现异常。**这就是本文档要建的系统。**

### 1.3 当前已实现的 demo 全貌

| 模块 | 路径 | 跑在哪 | 状态 |
|---|---|---|---|
| 后端 API + WebSocket | `packages/backend` | Mac dev / 阿里云 ECS 生产 | ✅ 已用 |
| Chrome 插件（泰康采集） | `packages/extension` | 员工 Chrome | ✅ 已用 |
| Tray-App（员工桌面客户端） | `packages/tray-app` | 员工 Windows 笔记本 | ✅ 已用 |
| 手机端（通话/录音上传） | `packages/mobile-*` | 员工手机 | ✅ 已用 |
| Capture Sidecar（截图采集） | `packages/capture-sidecar` | 员工 Windows | ⚠️ 现场版默认不启用，代码留着 |
| **管理后台（admin-web）** | **本文档要造** | **同后端 ECS** | ❌ **未开始** |

## 2. 系统架构总览

```
                                          ┌─────────────────────────┐
  员工 Chrome ─插件采订单─┐                │  阿里云 ECS              │
                          │                │                          │
  员工 Tray-App ─粘贴素材─┼───WS/REST──→  │  Fastify (backend)       │
                          │                │   │                       │
  员工手机 ─通话/录音─────┘                │   ├─→ PostgreSQL         │
                                            │   └─→ MinIO             │
                                            │                          │
   管理员浏览器 ───────────────HTTP───→     │  admin-web (本项目) ←──┐│
                                            └─────────────────────────┘
```

**关键事实**：

- **后端是 Fastify**，入口 `packages/backend/src/index.ts`。所有 REST 在 `packages/backend/src/routes/api.ts`。
- **数据库是 PostgreSQL via Prisma**，schema 在 `packages/backend/prisma/schema.prisma`。
- **对象存储是 MinIO**，bucket：`order-attachments / recordings / screenshots / materials`。
- **现行鉴权机制**：所有 REST 用 `X-Employee-Code` header，后端 hook 把 employee 注入 `request.employee`。WS 连接用 `?employeeCode=xxx&client=ext|tray` query。员工 ID 在三端（chrome 插件 popup / tray-app 设置 / 手机 app）必须一致。
- **manager 用户目前不存在**，员工和管理员混在 `employees` 表里——admin-web 需要**自己加一套独立的管理员鉴权**（详见 §7）。

## 3. 数据模型速览

完整 schema 看 `packages/backend/prisma/schema.prisma`。这里只列管理后台会用到的核心表：

### 3.1 `Employee` 员工
- `id / name / phone / token`（token 就是 employeeCode，员工自己填的）
- 一个员工拥有 0..N 个 Order / Material / Call

### 3.2 `Order` 订单
- `source='taikang'` / `sourceOrderNo`（泰康 subOrderNo）
- `customerName / customerPhone / hospital / dept / doctor / status`
- `assignedEmployeeId` 指向员工
- `rawJson`（chrome 插件采的**列表项**原始 JSON，含 `poolType: 'register'|'general'` 分挂号/绿通业务）
- `detailJson`（chrome 插件采的**订单详情**，结构是 `{ recommendations: { ... } }`，扁平挂着 paMobile / intendHos / intendDept / orderStateName 等数十字段）
- `detailFetchedAt` 详情抓取时间

### 3.3 `OrderAttachment` 订单附件
- 一个订单的若干附件（身份证 / 社保卡 / 病历 / 其他证件）
- `fileType / fileName / mimeType / minioBucket / minioKey / byteSize`

### 3.4 `Material` **现场采集素材** ⭐核心
- 员工在 tray-app 里"粘贴"或"手工录入"产生的客户沟通内容
- `type='text'|'image'` / `textContent` 或 `minioBucket+minioKey`
- `orderId` / `employeeId`
- `clientUuid`（本地生成，幂等键）
- 这是这次 demo 主要要看的"采集结果"——客户聊天文字、截图、电话语音整理稿都进这表

### 3.5 `Call` 通话记录
- 来自员工手机的通话上传
- `phone / direction / durationSec / startedAt`
- `recordingOssKey`（MinIO 音频文件）
- `asrText`（Fun-ASR / DashScope 转写文本）
- `asrStatus='no_recording'|'pending'|'processing'|'done'|'failed'|'requires_manual'`
- `orderId` 关联订单（按手机号自动匹配 / 员工手动归属）

### 3.6 `Message` 微信/企微消息（**本期 demo 不再用**）
- 原本为自动 OCR 截图设计的，现场版改成员工手工粘贴到 `Material` 表，所以 `Message` 表本期不会有新数据。**管理后台不需要展示它**。

## 4. 管理后台功能需求

### 4.1 核心使命

老板（本系统使用者）每天可能花 10 分钟看一次后台，他需要在那 10 分钟内得到三个问题的答案：

1. **数据在不在流？** 各端有没有掉线，今天采到多少新东西？
2. **数据质量怎么样？** 有没有某员工根本不录素材，有没有大批同步失败？
3. **有没有 bug？** 比如某订单插件抓了但详情没回，某员工通话上传后 ASR 一直 pending……

整个 UI 设计要服务于这三个问题。

### 4.2 必做功能（MVP）

#### 4.2.1 首页：仪表盘

一屏内能扫到全貌：

**顶部指标卡片**（实时刷新，每 10 秒）：
- 今日新增订单数（按 poolType 分挂号/绿通）
- 今日新增素材数（按 type 分 text/image/audio）
- 今日新增通话数 + 转写完成率
- 在线员工数（WS 当前活跃连接 / 总员工数）

**第二行图表**：
- 近 7 天每日素材采集量（堆叠柱：text/image/audio）
- 近 7 天订单状态分布（用泰康 `orderStateName` 原文当 facet）

**第三行警告区**（颜色突出）：
- 红：泰康 token 失效的员工列表（来自 `presenceMap.tokenOk=false`）
- 红：连续 X 小时（默认 6）没收到任何素材的员工
- 黄：详情抓取失败率 > 10% 的员工
- 黄：sync_status='failed' 的 material 数量 > 0
- 黄：asr_status='failed' 的 call 数量 > 0

#### 4.2.2 员工列表

表格视图：
- 员工 ID / 显示名
- 最后在线时间（WS）/ 当前 client 类型（ext/tray）
- 泰康 token 状态 / 最近一次检测时间
- 累计订单数 / 本周新单
- 累计素材数（按 type 分）/ 最近粘贴时间
- 累计通话数 / 转写完成 / 失败
- 操作：→ 进入员工详情

#### 4.2.3 员工详情

为每个员工提供一个"驾驶舱"：

**Tab 1: Presence 历史**
- 最近 24 小时 WS 在线/离线时间线
- 泰康 token 状态变化时间线
- 详情接口失败次数

**Tab 2: 订单**
- 该员工名下所有订单的表格（沿用 tray-app 工作台一样的字段，多加几列：详情抓取时间 / 附件数 / 素材数 / 通话数）
- 默认按 `lastMaterialAt` 倒序——能一眼看到"哪些单还在活跃产生数据"
- 支持搜：订单号 / 申请号 / 客户 / 手机 / 医院

**Tab 3: 素材流水**
- 时间线视图，倒序，分页
- 每条素材展示：时间 / 类型图标 / 关联订单（点击进订单详情）/ 内容预览（文本 300 字截断；图片缩略图）
- 按订单聚合的折叠视图（可选）

**Tab 4: 通话流水**
- 同上，按 startedAt 倒序
- 显示：phone（对方）/ direction / duration / asrStatus / asrText 预览
- 状态非 done 的高亮

#### 4.2.4 订单详情页

打开任意订单能看到这个订单**全部存留的数据**：

- **header**：订单号 / 申请号 / 客户 / 状态 / 申领员工 / 各时间
- **泰康详情字段表**：把 `detailJson.recommendations` 里所有非空字段铺出来（已知字段做语义化中文标签，未知字段原样显示 key=value）。**字段映射可参考 `packages/tray-app/src/renderer/src/components/OrderDetailModal.tsx`，那里已经做过中文标签**
- **附件画廊**：列出 OrderAttachment，图片用 presigned URL 直接预览（图片预览参考现有 `/api/v1/orders/:id/detail` 的 presigned 生成）
- **素材时间线**：所有 Material 倒序展示，文字直接显示，图片直接显示
- **通话时间线**：所有 Call 倒序展示，能播放录音（presigned MP3），能看转写文本
- **JSON debug**：底部一个折叠区，显示 `rawJson` 和 `detailJson` 完整 JSON

#### 4.2.5 素材浏览页

跨订单的 Material 全表浏览：
- 默认按时间倒序
- 列：时间 / 员工 / 订单（订单号 + 客户名）/ 类型 / 同步状态 / 内容预览
- 筛选：员工 / 时间范围 / 类型 / 同步状态
- 搜索：textContent 模糊匹配
- 点击进入"素材详情"（图片大图 / 文字全文 + 关联订单的上下文）

#### 4.2.6 系统健康

一个单独的"运维"页：
- 后端进程信息（uptime / Node 版本 / pid）
- DB 连接状态 + 表行数（Order/Material/Call/Attachment 计数）
- MinIO 健康（每个 bucket 的对象数 / 占用空间）
- WebSocket 当前连接数 + 客户端类型分布
- ASR 任务队列长度（pending + processing）+ 近 24h 成功率
- Chrome 插件最近一次成功上报时间（每个员工分别看）

### 4.3 选做功能（时间充裕再做）

- **导出**：素材按订单 / 按员工打包下载（ZIP）。CSV 导出 Material 列表
- **管理员告警**：可配规则，命中后发邮件 / Webhook（如某员工 24h 无素材）
- **数据脱敏开关**：管理员视图默认显示真实手机号 / 身份证，但有个开关切到脱敏，方便对外演示
- **审计日志**：管理员的查看 / 导出操作落日志
- **多管理员**：现在只支持单 admin，后续可能加角色

### 4.4 **明确不在范围内**

- ❌ 不做任何"反向操作员工 tray-app"的功能（这是只读后台）
- ❌ 不做用户管理（员工怎么创建？现在是员工填 code 自动 `upsert`，本期不动）
- ❌ 不做申领 / 派单等业务逻辑（不是寰宇核心系统，是个采集 demo）
- ❌ 不展示 `Message` 表（本期没数据）
- ❌ 不做 AI 分析 / 总结 / 还原（采到数据再说，等下一期）

## 5. UI 设计要点

### 5.1 整体风格

- **暖白底色**（参考已有 tray-app 的 Claude 风格主题：`packages/tray-app/src/renderer/src/assets/main.css`）。两个产品风格一致，**强调色用 #B8902E（琥珀黄）**
- 支持浅色/深色 + 跟随系统
- 左侧固定窄导航（仪表盘 / 员工 / 订单 / 素材 / 通话 / 系统健康 / 设置）
- 主体区域不超过 1280px 居中

### 5.2 关键交互

- **实时更新**：仪表盘 + 健康页用 WebSocket 推送 + 客户端 5 秒兜底刷新
- **跨表跳转**：素材里任何"订单 / 员工"都是可点击链接
- **图片预览**：点缩略图 → 全屏 lightbox，可滚轮缩放，Esc 关闭
- **长文本**：默认 300 字截断 + "展开全部"按钮，避免一条聊天记录撑爆屏幕

### 5.3 空状态 / 错误态

- 数据为空时给清晰的引导文案，不要默默白屏
- API 401 → 弹登录窗，不要硬跳走
- API 500 → 顶部红条 + 重试按钮

## 6. 后端 API 新增清单

> 不动现有员工端 API，所有新加的都挂在 `/api/v1/admin/*` 路径。

### 6.1 鉴权

新建 `/api/v1/admin/login` 接受 `{ password: string }`，匹配环境变量 `ADMIN_PASSWORD` 后签发 JWT（HS256，过期 12h），存 `httpOnly` cookie。后续所有 `/api/v1/admin/*` 都需要这个 cookie。

环境变量：
- `ADMIN_PASSWORD`：管理员明文密码（demo 阶段允许；后续上 bcrypt）
- `ADMIN_JWT_SECRET`：签发密钥

### 6.2 业务 API

下表只给签名，实现细节由 coder 决定。返回都遵循现有约定 `{ data: ... } | { error: string }`。

| Method | Path | 用途 |
|---|---|---|
| GET | `/api/v1/admin/dashboard/summary` | 仪表盘顶部卡片 + 当日统计 |
| GET | `/api/v1/admin/dashboard/timeseries?days=7` | 7 日折线/柱状数据 |
| GET | `/api/v1/admin/dashboard/alerts` | 当前所有告警（token 失效 / sync failed 等） |
| GET | `/api/v1/admin/employees` | 员工列表 + 统计 |
| GET | `/api/v1/admin/employees/:id` | 员工详情卡片数据 |
| GET | `/api/v1/admin/employees/:id/presence-history?hours=24` | Presence 时间线 |
| GET | `/api/v1/admin/employees/:id/orders` | 员工名下订单 |
| GET | `/api/v1/admin/employees/:id/materials?cursor=...` | 员工素材流水（cursor 分页） |
| GET | `/api/v1/admin/employees/:id/calls?cursor=...` | 员工通话流水 |
| GET | `/api/v1/admin/orders?search=...&employeeId=...` | 全部订单浏览 |
| GET | `/api/v1/admin/orders/:id/full` | 订单详情聚合（rawJson + recommendations + attachments + materials + calls 一次返回） |
| GET | `/api/v1/admin/materials?cursor=...&filters=...` | 跨员工素材浏览 |
| GET | `/api/v1/admin/materials/:id` | 单条素材详情，图片附 presigned URL |
| GET | `/api/v1/admin/calls?cursor=...&filters=...` | 跨员工通话浏览 |
| GET | `/api/v1/admin/health` | 系统健康（DB / MinIO / WS / ASR） |
| WS | `/ws/admin` | 管理员实时推送：新素材、新通话、新告警 |

### 6.3 实现注意

- **MinIO presigned URL 1 小时过期就够**，参考现有 `presignedGetObject(bucket, key, 60*60)`
- **WebSocket 复用**：可以在现有 `@fastify/websocket` 路由上加 `/ws/admin` endpoint，跟员工 WS 平级
- **大查询要游标分页**，不要 offset，避免后期数据量大慢查询。Material 已经按 createdAt 索引，按 (createdAt, id) 做 keyset 分页
- **不要用 `SELECT *`**：管理后台主要看派生统计，Prisma 用 `select` 明确字段，省带宽

## 7. 技术栈与项目结构

### 7.1 推荐栈

| 项 | 选型 | 理由 |
|---|---|---|
| 前端框架 | **React 18 + TypeScript** | 与 tray-app 一致，shared-types 可复用 |
| 构建 | **Vite** | 轻、快、配置少 |
| 路由 | **React Router v6** | SPA 标配 |
| 状态/请求 | **TanStack Query (React Query)** | 服务器状态首选，自动缓存 + 失效 + 重试 |
| 样式 | **Tailwind CSS v4** | 与 tray-app 一致，复用主题变量 |
| 图表 | **Recharts** | 简单够用，能塞进 React |
| 表格 | **TanStack Table** | 大数据排序筛选标配（虚拟滚动可选） |
| WS 客户端 | 浏览器原生 + 一个薄封装 | 不用 socket.io，后端是裸 WS |

### 7.3 构建与部署

- `pnpm --filter admin-web build` 产物在 `packages/admin-web/dist/`
- 后端 Fastify 用 `@fastify/static` 把这个 `dist/` 挂到 `/admin/*` 路径（生产）
- 开发时 vite dev server 跑在 5174，反向代理 `/api/v1/admin/*` 到 backend 13000
- 现有 `packages/backend/.env` 加两个新 var：`ADMIN_PASSWORD`、`ADMIN_JWT_SECRET`

### 7.4 阿里云 ECS 部署

- 后端 + admin-web 同一台 ECS：用 pm2 跑 `node packages/backend/dist/index.js`，Fastify 同时服务 API + 静态前端，监听单端口
- Nginx 反向代理到 ECS 公网域名 + Let's Encrypt 证书
- 数据库和 MinIO 跟现在一样跑在本机 Docker（或后期挪到 RDS / OSS）

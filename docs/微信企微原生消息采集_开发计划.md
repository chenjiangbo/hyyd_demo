## 按实际使用场景推进

### 1. 先确保集成代码能打包运行

- 对齐采集器协议、Electron 管理器、后台规则、后端入库和附件上传字段。
- 用企微源数据库递增行号追踪新写入记录，避免“新写入但消息时间很旧”被时间游标漏掉；保留最近 5 分钟的记录检查附件变化。
- **待确认附件边界：**如果旧消息的文件在发送超过 5 分钟后才下载到本机，目前的时间窗口不保证再次发现。需要先在 Windows 实测下载时点，再决定是否加入待补附件清单。
- 后台规则同步成功后保存已选会话；后台暂时离线或客户端重启时按本机最后保存的会话继续采集。
- 企微每 2 分钟扫描一次；微信持续轮询。之后在 Windows 实测端到端延迟。
- 在 Windows 构建两个采集器和寰宇医道测试安装包。
- 为手测准备可从 Windows 访问的测试后台：应用当前数据库结构/迁移，部署采集配置、发现、入库和附件接口；管理端打开“会话采集范围”设置规则，并用“微信与企微采集记录”核对已入库消息和附件。当前仍待确定/准备该测试后台的可访问地址和登录账号。
- 验证客户端与采集子进程的启动、退出、错误提示和重启；不停止、不修改同机 Broker Python。
- 采集周期按不超过 2–5 分钟的目标调整并实测端到端耗时，不能只看定时器配置。

### 2. 在 Windows 验收企微，再验收微信

覆盖客户的实际启动顺序：

- 寰宇医道客户端先启动，微信/企微随后启动并登录；采集应自动开始。
- 微信/企微在寰宇医道客户端运行期间退出，稍后重新启动；采集应恢复，不需重启寰宇医道客户端。
- 运行中在后台新增会话订阅；客户端定时刷新规则后应开始采集新会话，不需重启客户端。当前客户端规则刷新间隔为 30 秒，仍需实测实际生效时间。
- 三个客户端通常同时运行时，按后台规则只采指定业务会话。
- 企微启动时识别当前 profile 和正确数据目录；运行中切换企业时暂停，重启寰宇医道客户端后使用新企业目录。
- 对已配置会话核验文字、图片、文件、合并消息的来源时间、顺序、父子关系、附件字节/hash、入库和存储读取。
- 核验增量、去重、分页、断网/重启后的补采；端到端延迟控制在用户要求的 2–5 分钟内。

我们的开发验收以确保代码逻辑、Windows 打包和基本链路可用为主，不会用大量模拟测试代替真实验证。每一步如必须用户在 Windows 登录、发送消息、打开/下载文件或切换企业，我会明确告知具体动作。

### 3. 接入现有业务逻辑

- 复用现有会话归属订单/申请单、订单号解析和派单模板识别逻辑，不重做业务规则。
- 保留原生消息的来源 ID、类型、时间、附件和合并结构；再把会话/消息关联到现有订单或申请单，使现有业务能消费这些消息。
- 对无匹配或多匹配的会话沿用现有业务处理方式，并在真实数据上核对匹配结果。

## 完成标准

- Windows 客户测试包能在微信/企微先于或后于寰宇医道启动时正常采集，并能在聊天软件重启后恢复。
- 配置会话的消息和附件进入后端、顺序正确，并在 2–5 分钟目标内到达；未配置会话不采集正文。
- 企微当前企业对应的数据目录正确；切换企业后按“重启寰宇医道客户端”规则运行。
- 消息能进入现有订单等业务逻辑，且保留原生消息和附件信息。
- 你在客户 Windows 环境手工测试通过。

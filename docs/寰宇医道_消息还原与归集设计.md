# 寰宇医道 企微/微信消息 还原与归集设计

> 现行方案（取代早期"OCR+VLM 分区"思路）。
> 目标：把整天采集的大量截图，沉淀成"每个会话一份去重后的消息集合（部分带时间）"，再交 AI 整理/提取。
> 背景见 `寰宇医道_员工日常工作流.md`。

## 总体管线

```
第0层 图片去重（已实现，保留）
  落盘前视觉 diff + heartbeat，挡掉静止/重复帧
        ↓ 关键帧（本地磁盘 + capture.db，带 Windows OCR 文本及坐标）
第1层 OCR 标题过滤 + 归组（新增，用 OCR，不用 AI）
  取每帧"最靠上的 OCR 文字块"作标题候选（企微/微信统一规则）
  - 命中「手机号+姓名」→ 客户 1v1 会话，按该标题归组
  - 群标题含「泰康」→ 泰康工作群，按该标题归组
  - 都不命中 → 丢弃，不送 AI
        ↓ 仅"客户/泰康群"的帧，已按会话分好组
第2层 AI 消息还原（已实现：qwen3-vl-235b-a22b-instruct，走百炼）
  每个会话攒一小批(带重叠)→ 还原成消息列表；可见的时间填入 time 字段
        ↓ 一批批的还原结果
第3层 按会话合并 + 去重（新增）
  把各批结果并入该会话的"消息集合"，按 (sender, 归一化content) 去重
  不强求严格时序；用可见的 time 作软排序锚点 → 得到"部分带时间、去重后的消息集合"
        ↓
第4层 AI 整理 + 提取（新增，文本，暂自由发挥）
  对某会话的消息集合，让 AI 自由整理、提炼关键信息（字段暂不固定，待调研泰康/寰宇系统后再约束）
```

## 关键规则

### OCR 标题识别（第1层）
- 数据来源：采集 sidecar 已在保留帧上跑 Windows OCR，**带 bbox 坐标**，存于 capture.db。
- 统一规则：按 y 坐标取**最靠上**的文字块作标题候选；同时允许"模式在整段 OCR 文本任意位置出现"作兜底。
- 客户匹配：正则 `1\d{10}#中文姓名`，例如 `13683106089#张文娟`（员工把客户改名为「手机号#姓名」，企微/微信都要求；`#` 分隔符独特、OCR 不易误判）。
- 群匹配：标题含「泰康」（群名由运营统一）。
- 不命中（既非"手机号#姓名"也不含"泰康"）默认**丢弃**（省钱/过滤公私不分）。

### 合并去重（第3层）
- 范围：**按会话 key（标题）**聚合，可跨天连续。
- 去重键：`sender + 归一化后的 content`（去空白/标点波动）。
- 排序：尽量用可见 time 作锚点；员工往回翻历史会让旧消息重现/乱序，**不追求精确 transcript**，接受"大致有序的去重集合"。

### 两段式 AI
- 第2层（图→消息）：多模态，qwen3-vl，走百炼（国内直连）。
- 第4层（消息→信息）：纯文本，可用更便宜的文本模型；当前**自由提取**，不固定字段。

## 架构分工（待定细节）
- AI 还原当前在 **tray-app 主进程**发起（截图只在 VM 本地）。
- 倾向：tray-app 负责 第1~3层（筛选/还原/合并），把**文字结果**发后端存"会话权威集合"（图不上传）；第4层可在后端。
- 候选存储：capture.db 已有 `conversation_threads` / `message_blocks` 表（早期遗留），可复用来存 AI 合并后的会话消息。

## 已确认决策
1. **触发方式**：现阶段第2层还原**先手动**（AI 还原页按会话选）跑通合并去重，之后再做自动。
2. **权威存储位置**：测试期存 tray-app 本地 capture.db（复用 `conversation_threads`/`message_blocks`），生产再议。
3. **跨天**：同一会话 key（标题）跨天聚合成一条连续集合。
4. **不命中处理**：标题既非"手机号#姓名"也不含"泰康" → 直接丢弃，不处理。

## 测试方法
- 在 VM 的微信/企微里：客户联系人改名为「手机号+姓名」，群名带「泰康」，模拟真实规范。
- 先验证 第1层"读标题→过滤→归组"是否准确，再接 第3层合并去重，最后试 第4层自由提取。

# 寰宇绿通工作台 · 功能设计（最终功能版）

> 本文档面向 UI/UX 设计师，描述「寰宇绿通工作台」桌面端应用的**功能与交互结构**，
> 用于指导界面设计。文档只定义"要有哪些功能、信息怎么组织、关键交互怎么走"，
> 不规定具体视觉风格（配色、字体、间距由设计师把握）。

---

## 一、业务背景

寰宇医道是一家为保险客户提供**医疗绿色通道服务**的机构。客户购买了保险公司（泰康、平安等）的健康服务权益后，由寰宇的**服务专员**负责落地这些服务，主要包括：

- **挂号协助**：帮客户挂上指定医院、科室、专家的号
- **绿通业务**：陪诊、住院协调、检查加急、专家会诊等多种细分服务

**专员的日常**：一个专员同时负责几十到上百个订单，单个订单往往跨多天交付。订单从保险公司的系统流入，专员需要先**申领**订单，然后通过**微信 / 企业微信 / 电话**与客户沟通，了解并确认需求，协调医疗资源，最终完成服务并把关键信息**回填**到保险公司系统和寰宇自己的订单系统。

**这款应用要解决的核心问题**：
1. 专员的沟通过程（电话、微信、图片）目前散落各处、无沉淀，事后无据可查。
2. 从沟通里整理出"要回填进系统的关键信息"全靠人工，费时且易错。
3. 管理者无法实时掌握团队的服务进展和质量。

**这款应用的定位**：专员每天工作的主场所。把订单管理、客户沟通沉淀、AI 关键信息提取、知识沉淀集中到一处——让专员活更轻松，数据资产顺势沉淀。

---

## 二、整体结构

桌面应用（Windows 为主），**一级导航位于顶部**（横向 Tab），共 5 个：

| 顶部导航 | 作用 |
|---|---|
| **待申领** | 保险公司候选订单池，专员在此"抢单"申领 |
| **工作台** | 主战场。已申领订单的泳道看板 + 单订单详情 |
| **客户档案** | 跨订单查看同一客户的完整画像 |
| **知识库** | 沉淀"怎么挂上号/找哪些资源"的经验 |
| **数据看板** | 全公司及各专员的服务统计 |

> 设计提示：5 个一级 Tab 始终常驻顶部。应用整体应给人"工作台/驾驶舱"的感觉，专员一天大部分时间停留在【工作台】。

## 三、待申领

候选订单池：尚未被任何专员申领的订单，先到先得。

**功能**
- 列表展示候选订单，每条显示：来源（泰康/平安）、客户、业务类型、诉求摘要、进入候选池时间
- **「申领」** 操作：专员点击后系统完成申领，订单转入该专员的【工作台】
- 支持搜索

**设计提示**
- 【待申领】是"市场/抢单"心智，【工作台】是"我的活儿"心智，两者视觉上要明显区分。
- 申领是高频操作，按钮要醒目、点击反馈要清晰（申领中/申领成功/已被他人申领）。

---

## 四、工作台

申领成功的订单落到这里，是应用的核心区域。分两个层级：**泳道看板** → 点进 → **单订单详情**。

### 4.1 泳道看板

按**订单状态**分泳道。状态是**绿通和挂号共用的抽象状态**，不按业务类型分（业务类型是订单内部字段）。共 4 条泳道：

| 泳道 | 含义 |
|---|---|
| **待处理** | 刚申领，尚未开始联系客户 |
| **进行中** | 正在与客户沟通 / 服务交付中 |
| **待确认回填** | AI 已提取出足够的关键信息，等专员与客户确认后回填系统 |
| **已完成** | 服务交付完毕、信息已回填 |

**功能**
- 订单卡片可在泳道间流转（拖动或在详情内改）
- 卡片信息：客户名、业务类型（挂号/陪诊/…）、来源、医院·科室、"距上次联系 X 天"、超时预警角标
- 顶部搜索

**设计提示**
- "待确认回填"泳道是关键环节，要让专员一眼看出"这单 AI 准备好了，去找客户确认就能回填"，视觉上可适当强调。
- 泳道数量未来可能增加，看板布局要能容纳第 5 条而不崩。

### 4.2 单订单详情

订单详情承载的信息很多，采用 **「顶部条 + 左中生命周期轴 + 右侧标签页面板」** 的布局，配合少量弹窗收纳，避免一页塞爆。

#### A. 顶部条（常驻）

显示订单的身份信息：

- 客户名
- 业务类型（挂号 / 陪诊 / 住院协调 / …）
- 来源（泰康 / 平安）
- **医院 · 科室**（必须显示）
- 关键联系方式

> 不在顶部条重复显示"当前状态"——当前所处阶段由下方的生命周期轴呈现。

#### B. 左 / 中 —— 生命周期阶段轴（核心）

这是一条**订单生命周期的阶段轴**（不是按时间排列的流水时间线）。它表达"这个订单走到了哪一步"。

绿通与挂号当前**共用同一条抽象生命周期**（未来不同业务类型可定制各自的轴，本版先统一）：

```
已申领 → 需求沟通 → 资源协调 → 服务交付 → 信息确认回填 → 完成
```

**功能**
- 高亮当前所处阶段，已完成阶段与未到阶段视觉区分
- 每个阶段节点下挂该阶段产生的过程数据与材料：
  - 通话录音 + 转写文本
  - 粘贴进来的微信消息 / 图片
  - 手工补录的条目
  - 系统事件（申领、阶段流转、回填等）
- 点击录音、图片等可放大查看（见弹窗说明）

**设计提示**
- 阶段轴是详情页的视觉重心，要清楚表达"订单进展"这件事。
- 同一阶段下可能挂多条材料，需要可展开/收起，避免轴被材料撑得过长。

#### C. 右侧 —— 信息面板（标签页）

右侧是一个带标签页的面板，**默认显示「数据补录」页**：

**标签页 1：数据补录（默认）**
- 专员手工补录关键信息的地方（电话要点、线下沟通到的信息等），就地编辑，无需弹窗
- 与 AI 提取的信息可并列/互补

**标签页 2：AI 关键信息**
- AI 从过程数据（通话转写、粘贴的微信文字/图片）中**自动**提取出的结构化关键信息
- 这些信息就是未来要回填进泰康/平安/寰宇订单系统的数据（就诊意向、客户诉求、就诊人信息、特殊情况等）
- 提供「重新提取」按钮，支持手工触发；但常态是**自动提取**——有新过程数据即后台更新

> 本版 AI 的唯一职责就是**关键信息提取**。不做动作建议、不做回复起草等高级功能。

#### D. 关键信息回填（消息提醒 + 弹窗）

这是 AI 与专员协作的关键交互：

1. 当 AI 判断**信息已足够回填**时，在界面**右上角弹出一条消息提醒**。
   - ⚠️ 消息提醒**严格克制**，只有"需要专员确认才能继续"的关键节点才提醒，不得滥用。
2. 专员点击该提醒 → **弹出回填确认弹窗**，展示"将要回填的字段清单"。
3. 专员可在弹窗内**手工修改**这些字段，并先与客户确认信息无误。
4. 点击「回填」→ 系统**自动回填**到对应系统，订单进入/离开「待确认回填」状态。

> 本版做到"生成可回填数据 + 专员确认 + 触发回填"的完整闭环。

#### E. 弹窗清单（用于收纳，避免主页拥挤）

- **大图 / 录音详情弹窗**：查看图片大图、播放录音、看转写全文
- **回填确认弹窗**：见上 D

> 手工补录**不用弹窗**，在右侧「数据补录」标签页就地完成。

## 五、客户档案

同一客户可能多次来（这次挂号、下次陪诊）。客户档案按客户聚合，给专员一个 360° 视图。

**功能**
- 按客户聚合其所有历史与在途订单
- 基本信息 + 保单信息
- 病情 / 就诊历史
- 历史服务记录
- 沟通偏好（常去医院、方便联系的时段等）——这些可由 AI 从过程数据中逐步沉淀

**设计提示**
- 入口：可从订单详情的客户名跳转，也可在【客户档案】Tab 内搜索。
- 重点是"第二次接触这个客户时，专员能迅速回忆起他是谁、上次发生过什么"。

## 六、知识库

沉淀"怎么把号挂上、找哪些资源靠谱"的经验。现状只有医院/科室的基础码表，本版做一个**轻量起点**，结构上分两层：

- **基础层**：医院、科室、专家（来自现有码表）
- **经验层**：挂在每个医院/科室/专家/资源上的经验注记，例如
  - 某医院某科室是否好挂、需提前多久
  - 某专家是否很难约、约不上一般引导去哪
  - 外部资源（号源/陪诊）的口碑（敏感内容，需权限控制）

**功能（本版）**
- 浏览基础层信息
- **手工记录一条经验注记**，并保留"经验来自哪一单"的溯源

**设计提示**
- 本版只做"能看 + 能手工记一条经验"，结构上为未来"从订单数据自动提炼经验"预留空间。
- 经验层内容随订单数据增长而丰富，界面要能体现"经验在不断累积"的感觉。

---

## 七、数据看板

面向全公司和管理者的服务统计（只看统计，不看明细）。

**功能**
- **全公司维度**：总单量、完成率、各业务类型分布、服务时效等
- **按专员维度**：每个专员的订单处理情况统计
  - 分类统计，**绿通需细分到具体绿通类型**（陪诊 / 住院协调 / 检查加急 / 专家会诊 …）
  - 只要统计数据，不需要订单明细

**设计提示**
- 看板以图表为主，强调"一眼看清团队整体状态与各专员负载/产出"。

---

## 八、本版功能边界（明确不做）

- 任务/提醒系统（专员用手机闹钟 + 114/医院小程序完成挂号，本应用不介入）
- AI 高级功能（动作建议、回复起草、自动提炼知识库经验等）
- 真正写回各保险系统由系统自动完成，本版聚焦"生成可回填数据 + 专员确认 + 触发回填"的闭环

## 附：术语表

| 术语 | 含义 |
|---|---|
| 申领 | 专员从候选池领取一个订单，归属到自己名下 |
| 绿通 | 医疗绿色通道服务的统称（陪诊、住院协调、检查加急、专家会诊等） |
| 挂号协助 | 帮客户挂上指定医院/科室/专家的号 |
| 回填 | 把整理好的关键信息写回保险公司系统及寰宇订单系统 |
| 过程数据 | 服务过程中产生的原始材料：通话录音/转写、微信消息、图片、手工补录 |
| 关键信息 | AI 从过程数据中提取、用于回填的结构化字段 |

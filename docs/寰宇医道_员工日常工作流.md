# 寰宇医道 员工日常工作流

> 业务背景文档。描述一线员工（客户经理/客服，负责医疗绿通业务）一天的真实工作内容，
> 作为采集（企微/微信消息、通话录音）、还原、信息提取等功能的设计依据。

## 总体特征

员工一天的工作**不是线性流程，而是以下几件事穿插进行**——会随时被电话、闹钟、客户消息打断，在多个订单/客户之间来回切换。

## 主要工作环节

### 1. 申领订单、查看需求
- 在系统里点"申领"，拿到订单。
- 查看订单的需求内容。

### 2. 给客户打电话
- 电话进一步了解客户需求。
- 对于**难以满足的需求**，会引导客户到别的医院或其他解决方式。
- 通话中通常会**引导客户加微信**，方便后续沟通。
  - **泰康的客户**：一般用**泰康的企业微信账号**来加；
  - **其他甲方（如平安）的客户**：用员工的**个人微信**来加。
  - → 这就是为什么采集要同时覆盖企微和微信两个渠道。

### 3. 闹钟提醒 → 给客户挂号
- 员工会给自己设定闹钟；到点（如放号时间）去给客户挂号。

### 4. 在微信/企微上与客户沟通
沟通内容按业务类型差异很大：
- **挂号业务**：相对简单，一般是反馈挂号情况。
- **绿通业务**：要沟通的事情非常杂，取决于具体是什么服务：
  - **陪诊**：需要找陪诊人员。陪诊资源来源多样：
    - 他们**配置库里**的（经常合作的固定资源）；
    - **医院的**；
    - 他们**自己的专家**。
  - **接送服务**等。
  - → 绿通的沟通和资源协调非常复杂。

### 5. 在泰康或寰宇自己的系统里填单
- **刚申领时**要填一次。
- **中间过程**还要继续填（订单生命周期数据需要持续完善）。
- 两套系统：**泰康的系统** + **寰宇自己的系统**。

## 对功能设计的启示（备忘）

- 采集需同时支持**企微**（泰康客户）和**个人微信**（其他甲方客户）。
- 一天内员工在**多个客户/订单、多个会话**之间频繁切换 → 采集到的截图天然属于不同会话，需要按会话归组。
- 沟通内容信息密度高、且分散在很长时间里 → 后续"关键信息提取/订单生命周期数据完善"会面临长内容、多来源（聊天 + 通话）聚合的问题。
- 最终目标包含把关键数据项**回填到泰康和寰宇系统**（回填泰康涉及写别人家系统，需单独评估）。

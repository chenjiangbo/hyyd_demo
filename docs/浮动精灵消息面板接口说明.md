# 浮动精灵消息面板接口说明

## 1. 目的

浮动精灵不是一个只能显示一句文字的提示窗口。它由两个独立部分组成：

1. 精灵角色：负责待机、接收文件、处理中、说话等视觉状态；
2. 消息面板：显示文字、进度、候选订单、表单和交互按钮。

业务代码只需要提交一个消息面板模型，不需要自己计算气泡位置、窗口大小或绘制表单。

## 2. 窗口尺寸规则

代码中的 `96 x 96` 不是精灵图片的业务尺寸，也不是气泡尺寸。它是空闲时透明 Electron 窗口的最小承载区域，里面实际角色约为 `64 x 70`。

代码中的 `300 x 260` 也不是展开后的固定气泡尺寸，而是有消息面板时的最小承载区域。实际窗口尺寸由气泡渲染后的内容计算：

- 短消息使用紧凑尺寸；
- 表单字段变多时，气泡根据内容增加高度；
- 内容超过屏幕可用高度时，表单内容区滚动，底部操作按钮保持可见；
- 窗口会根据精灵所在屏幕位置决定气泡显示在左侧还是右侧；
- 最大尺寸受当前屏幕边界约束，不允许遮挡整个屏幕或把按钮放到屏幕外。

调用方不应传入窗口宽高，也不应通过 CSS 强行定位气泡。

## 4. 消息面板模型

### 4.1 普通消息

适用于成功、提醒、说明等不需要填写数据的内容。

```ts
interface PetSpeechPanel {
  kind: 'speech'
  text: string
  actions?: PetAction[]
}
```

示例：

```ts
{
  kind: 'speech',
  text: '图片已经收到，我正在识别挂号信息。',
  actions: [
    { id: 'view-detail', label: '查看详情', action: 'custom' }
  ]
}
```

### 4.2 进度消息

适用于视觉识别、订单匹配、上传等进行中的操作。进度值可选；没有可靠百分比时只显示处理中，不得伪造百分比。

```ts
interface PetProgressPanel {
  kind: 'progress'
  text: string
  progress?: number
}
```

### 4.3 错误或需要用户处理的消息

```ts
interface PetErrorPanel {
  kind: 'error'
  text: string
  actions?: PetAction[]
}
```

错误面板必须给出业务含义和下一步动作，例如“图片上传失败，请检查网络”，而不是把异常堆栈显示给员工。

### 4.4 候选订单列表

```ts
interface PetCandidatePanel {
  kind: 'candidate-list'
  title: string
  items: Array<{
    orderId: number
    sourceOrderNo: string
    customerName: string
    hospital: string | null
    department: string | null
    appointmentDate: string | null
  }>
}
```

候选项本身就是可点击操作。点击后回传被选中的 `orderId`，业务模块再决定是否保存或继续处理。

### 4.5 表单面板

表单不是另一种窗口，而是消息面板的一种内容类型。它可以显示只读识别结果，也可以显示需要员工补充或确认的字段。

已有业务表单不需要重写。根据表单复杂度，采用两种接入模式：

- 简单表单：通过适配器转换成 `PetFormPanel`，复用原表单的校验和提交逻辑；
- 复杂表单：精灵只显示说明和操作按钮，点击后打开工作台中已经开发好的原表单。

不能把 React/Vue 组件、校验函数或提交函数直接放进 IPC 消息中。跨窗口传输的数据必须是可序列化的字段和事件。

```ts
interface PetFormPanel {
  kind: 'form'
  id: string
  title: string
  description?: string
  sections?: PetFormSection[]
  fields: PetField[]
  actions: PetAction[]
  submitState?: 'idle' | 'submitting' | 'success' | 'error'
}

interface PetFormSection {
  id: string
  title: string
  fieldIds: string[]
}

interface PetField {
  id: string
  label: string
  type: 'text' | 'textarea' | 'number' | 'date' | 'select' | 'radio' | 'checkbox'
  value: string | number | boolean
  placeholder?: string
  hint?: string
  required?: boolean
  readOnly?: boolean
  options?: Array<{ value: string; label: string }>
  error?: string
  validation?: {
    rule: 'required' | 'phone' | 'id-card' | 'date'
    message: string
  }
}
```

示例：挂号凭证识别后，请员工确认并补充缺失信息。

```ts
{
  kind: 'form',
  id: 'registration-proof-confirm',
  title: '请确认挂号信息',
  description: '我识别到这可能是一张挂号凭证，请确认后继续。',
  fields: [
    {
      id: 'patientName',
      label: '患者姓名',
      type: 'text',
      value: '张*三',
      readOnly: true
    },
    {
      id: 'hospital',
      label: '医院',
      type: 'text',
      value: '北京某医院',
      readOnly: true
    },
    {
      id: 'department',
      label: '科室',
      type: 'text',
      value: '',
      required: true,
      placeholder: '请输入或选择科室'
    },
    {
      id: 'idCardSuffix',
      label: '身份证后四位',
      type: 'text',
      value: '',
      required: true,
      validation: { rule: 'id-card', message: '请输入身份证后四位' }
    }
  ],
  actions: [
    { id: 'confirm', label: '确认保存', tone: 'primary', action: 'submit' },
    { id: 'choose-order', label: '重新选择订单', action: 'custom' }
  ]
}
```

## 5. 操作按钮模型

```ts
interface PetAction {
  id: string
  label: string
  tone?: 'primary' | 'secondary' | 'danger'
  action?: 'submit' | 'cancel' | 'retry' | 'custom'
  disabled?: boolean
  loading?: boolean
}
```

按钮的 `id` 是业务事件标识，不应该把函数、闭包或 Electron 对象放进面板数据。按钮点击后只回传：

```ts
{
  panelId: 'registration-proof-confirm',
  actionId: 'confirm',
  fields: {
    patientName: '张*三',
    hospital: '北京某医院',
    department: '心内科',
    idCardSuffix: '1234'
  }
}
```

业务模块收到事件后负责：

1. 校验字段；
2. 调用订单或上传接口；
3. 把 `submitState` 和字段错误重新发给精灵；
4. 成功后关闭面板或切换成成功消息。

精灵不负责订单保存、不负责上传，也不应该在没有业务接口成功结果时显示“保存成功”。

## 6. 已有表单适配器

简单表单使用适配器连接已有表单模型和精灵面板：

```ts
interface PetFormAdapter<T> {
  toPanel(value: T): PetFormPanel
  fromPanelValues(values: Record<string, unknown>): T
  validate(value: T): {
    valid: boolean
    errors: Record<string, string>
  }
  submit(value: T): Promise<void>
}
```

示例：

```ts
const registrationFormAdapter: PetFormAdapter<RegistrationForm> = {
  toPanel(form) {
    return {
      kind: 'form',
      id: 'registration-confirm',
      title: '请确认挂号信息',
      fields: [
        {
          id: 'patientName',
          label: '患者姓名',
          type: 'text',
          value: form.patientName,
          readOnly: true
        }
      ],
      actions: [
        {
          id: 'submit',
          label: '确认保存',
          action: 'submit',
          tone: 'primary'
        }
      ]
    }
  },

  fromPanelValues(values) {
    return { patientName: String(values.patientName ?? '') }
  },

  validate(form) {
    return existingRegistrationValidator(form)
  },

  async submit(form) {
    await existingRegistrationSubmit(form)
  }
}
```

提交过程必须由业务模块控制：

```text
精灵提交字段
  ↓
适配器 fromPanelValues
  ↓
复用原表单 validate
  ├─ 校验失败：updatePetPanel，回显字段错误
  └─ 校验成功：复用原 submit
                  ├─ 失败：更新错误状态
                  └─ 成功：更新成功消息或关闭面板
```

复杂表单不应为了适配精灵而压缩成一组简单字段。使用普通消息面板和跳转按钮：

```ts
{
  kind: 'speech',
  text: '这项资料需要在完整表单中确认，我带你打开原表单。',
  actions: [
    {
      id: 'open-registration-form',
      label: '打开完整表单',
      action: 'custom',
      tone: 'primary'
    }
  ]
}
```

点击后由业务模块调用现有工作台路由或窗口，不由精灵自己猜测页面地址。

## 7. 推荐的调用门面

正式接入时，业务模块使用 `PetController` / `window.api` 门面，不直接访问 React 组件：

```ts
window.api.showPetPanel(panel)
window.api.updatePetPanel(panelId, panel)
window.api.hidePetPanel()
window.api.onPetPanelAction((event) => {
  // 根据 event.panelId 和 event.actionId 调用业务代码
})
```

建议接口约束：

```ts
showPetPanel(panel: PetPanel): Promise<void>
updatePetPanel(panelId: string, panel: PetPanel): Promise<void>
hidePetPanel(): Promise<void>
onPetPanelAction(cb: (event: PetPanelActionEvent) => void): () => void
```

所有面板都必须有唯一 `panelId`。更新时必须带回同一个 `id`，防止旧请求覆盖新面板。

## 8. 生命周期

```text
业务模块
  │ showPetPanel(panel)
  ▼
主进程校验面板数据
  │
  ▼
浮动精灵渲染面板并测量内容
  │
  ▼
主进程按实际尺寸调整透明窗口
  │
  ├─ 用户修改字段 ──► 字段值事件
  ├─ 用户点击按钮 ──► PetPanelActionEvent
  └─ 业务处理结果 ──► updatePetPanel(...)
```

核心链路中，面板数据非法、`panelId` 缺失、按钮事件无法路由时必须报错，不能静默显示一个空气泡或伪造操作成功。

## 9. 不允许的调用方式

- 不要把固定 `300 x 260` 当作表单尺寸；
- 不要在业务页面里自行创建第二个窗口模拟气泡；
- 不要把函数放进 IPC 面板对象；
- 不要用省略号截断字段或按钮文字；
- 不要在精灵内部猜测订单、上传结果或移动端状态；
- 不要把前台/后台状态从一次心跳中推断出来。

## 10. 当前接入结论

当前 `PetBubble` 已具备上述内容渲染基础，表单控件和动态尺寸也已接入。统一的 `showPetPanel / updatePetPanel / hidePetPanel / onPetPanelAction` 门面已接入；复杂表单打开工作台的事件路由仍按具体业务实现。业务同事只需要选择简单表单适配器或复杂表单跳转，不需要了解 Electron 窗口和 React 组件细节。

寰宇订单 AI 面板使用列表点击时的订单号查询最新分析结果，并核对订单维护详情中的实际订单号；读不到或不一致时提示重新打开，不允许填写。面板展示只读的订单号、证件号码，以及订单状态、医院、医院地址、科室、医生、五项时间和可增减的陪诊记录（服务日期/时间、陪诊人、陪诊电话）。用户可修改候选值，点击“一键填单”后检查远端维表；缺失时提示确认创建，确认后直接 UPDATE 远端寰宇订单并刷新浏览器表单。返回列表、离开页面或关闭浏览器时关闭面板；浏览器窗口最小化或切换到其他应用时暂时隐藏面板，返回订单页面后恢复显示并保留已填写内容。点击精灵面板进行操作时，面板保持显示。

订单号用于展示、复制、订单身份核对和定位远端更新行；证件号码仅用于展示和复制。一键填单不提交证件号码，也不更新远端订单的证件号码。

陪诊记录至少保留一条。浮窗只在多于一条时提供移除操作，后台填单接口也拒绝零条陪诊记录。

订单页面识别规则由当前部署的管理后台维护：**系统设置 → 寰宇订单页面识别**。每套后台可保存多个站点地址（协议、域名或 IP、端口），共用一组订单列表资源 ID 和订单维护资源 ID；未配置时不启用识别。测试后台配置测试站点，生产后台配置生产站点。桌面精灵通过员工身份从当前后台读取规则，本机扩展约每 15 秒同步一次；保存后刷新业务页面即可检测。扩展不再提供逐台填写站点的入口。

扩展根据后台配置动态注册站点脚本，支持域名和 IP；协议、主机和端口必须与访问地址一致。保存配置后等待精灵和扩展同步，再刷新业务页面。此功能需要更新后的扩展。

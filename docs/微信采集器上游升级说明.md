# 微信采集器上游升级说明

## 现状

本项目使用 `wechatauto-replica` 的数据库和媒体读取代码，基础版本为上游 `v1.2.7.0`，随后在本项目内持续修改。上游项目还包括发送消息、朋友圈和界面操作等功能，我们的采集进程使用本地数据库及媒体读取，不调用这些功能。

2026-11-03 对照的上游版本为 `v1.2.9`，标签对应提交 `bc2e6f2461330eb1a53996d2f2afc18416376b52`。上游声明已在微信 4.2.0.11 验证相关功能；我们的集成版仍需在实际微信 4.2 客户端验证，不能仅凭上游声明判断全部采集功能正常。

## 本项目保留的功能

- `packages/native-chat-collectors/wechat/collector.py`：订阅会话采集、首次读取范围和分页、游标、消息及附件上报、补取和日志。
- `async_image_key.py`：后台获取图片密钥，避免密钥扫描阻塞消息采集。
- `vendor/wechatauto/db.py`：在上游数据库读取基础上增加消息游标、首次消息读取、会话时间及发送人解析等。
- `vendor/wechatauto/media.py`：在上游媒体读取基础上增加图片清晰度识别、WXGF 转换、文件匹配与歧义处理、合并消息附件定位和耗时日志等。
- `vendor/wechatauto/records.py`：合并消息内容解析。

## 本次 v1.2.9 对照

上游 `db.py` 的差异主要涉及数据库密钥缓存的 DPAPI 加密、连接关闭和文件短时不可读的处理。上游 `media.py` 增加了按目标图片验证密钥的修复，以及操作微信界面查看原图的适配。本项目采集器读取本地已有的媒体，不调用上游通过界面打开原图的流程。

本次将目标图片密文传入密钥验证，并使异步取密钥线程使用同一份密文。之前本项目已经处理了旧格式文件不适合作验证样本的问题，但验证仍可能沿用先前缓存的样本。保留本项目的媒体查找、转码、异常和耗时记录。

按用户决定，数据库密钥缓存仍使用现有明文格式；上游界面自动化能力也没有引入。数据库密钥扫描读取文件暂时失败时记录待恢复状态并继续扫描其他库，后台定期重试；消息分片不完整时不推进会话游标。因此当前集成版应标识为 **基于 1.2.7.0 并合入 1.2.9 图片密钥修复**，不能标记为完整的原版 1.2.9。

## 以后升级

1. 固定并记录当前上游标签和目标标签，下载两个版本的原始代码，比较 `db.py`、`media.py` 等本项目实际使用模块。
2. 将上游版本之间的改动与本项目的修改逐项对照；同时核对 `collector.py` 和异步密钥处理等调用方，避免接口变化导致采集失败。
3. 记录每项上游改动是否适用及处理结果，保留本项目的采集、游标、媒体和日志功能。
4. 运行现有采集器测试，增加覆盖本次变化的必要测试；在 Windows 微信旧版本与目标版本上对照会话、消息、发送人、图片、文件、合并消息、补取和游标。验证实际数据后才能认定兼容。
5. 用户要求打包时，将本地代码和新版采集器一起打入客户端，更新客户端版本号；保留可回退的安装包和对应源码版本。

## 本次逐项对照结果（2026-11-03）

对照来源为上游 `v1.2.7.0` 与 `v1.2.9` 两个标签，以及本项目当前采集器入口与导入关系。下表中的“不调用”仅指本项目微信采集器，不代表其他系统功能不存在。

| 上游改动文件 | 上游改动 | 当前采集用途与处理 |
| --- | --- | --- |
| `db.py` | Windows 用户加密数据库密钥缓存；读取明文和加密缓存；关闭联系人查询连接；扫描时处理数据库文件暂时不可读 | 采集器直接使用。图片密钥补丁没有覆盖这些改动。DPAPI 改变缓存格式，当前构建依赖没有 pywin32；需要同时考虑明文旧缓存、加密缓存、出错报告、构建依赖和旧版回退兼容，尚未合入。连接关闭不在当前采集调用路径，按用户决定暂不合入。密钥扫描读取数据库文件遇到系统错误时，记录未恢复的数据库并继续扫描其他库；后台每 60 秒检查并重试。消息分片不完整时不推进会话游标。上游这组差异没有明确标明是微信 4.2 数据库兼容修复。 |

| `wx.py` | 独立聊天窗口、发送、自动化接口 | 采集器不导入上游 `WeChat` 自动化入口。 |
| `__init__.py` | 上游导出接口和版本变化 | 当前裁剪后的包初始化文件仅供数据库与媒体模块使用，不能直接以原版初始化文件覆盖。 |

客户提供的日志记录的是 Node 启动 `hyyd-wechat-collector.exe` 时的 `spawn UNKNOWN`。该错误发生在采集器报告就绪以前，日志未提供 Windows 的详细错误码；它不能证明是微信 4.2 的数据库格式或密钥引起，也不能证明上游升级会修复它。现有新版客户端代码已加入启动错误字段、程序路径和文件状态日志，需要在出问题机器获取新日志来确定下一步。另一台 Windows 已检测到微信 4.2.0.12；上游明确列出的验证版本为 4.2.0.11，且当前尚未完成本项目采集链路的 4.2 实机验证。

## 数据库与图片恢复处理

- 会话数据库启动时暂不可读：采集器保持运行，记录错误并周期尝试；恢复后继续发现会话。
- 密钥扫描读取数据库头不足一页时，按暂不可读记录并后台重试。若消息分片不可用，现有完整性保护不推进会话游标。
- 图片使用已缓存的密钥前，按当前图片密文验证；密文不完整或单张图片验证失败时标记待重试，不增加整个账号的密钥失败次数。
